# Как участвовать в развитии KalimeraWG

Спасибо за желание улучшить проект. Изменения должны сохранять безопасность,
идемпотентность и возможность чистого развёртывания.

## Перед началом

1. Создайте Issue с описанием проблемы или предлагаемого поведения.
2. Сделайте fork и отдельную ветку для одного логического изменения.
3. Не используйте реальные серверы, ключи или учётные данные в тестах.

## Требования к изменениям

- пользовательский вывод и комментарии проекта пишутся по-русски;
- секретные Ansible-задачи сохраняют `no_log: true`;
- закрытые ключи, PSK, пароли, клиентские конфигурации, логи, `pcap`, runtime и
  резервные копии не добавляются в Git;
- новые параметры имеют безопасные значения по умолчанию и документируются;
- повторный deploy не должен создавать лишние изменения;
- операции с SSH и firewall не должны закрывать подтверждённый канал доступа до
  проверки нового;
- сторонний код и артефакты должны иметь закреплённую версию, checksum и
  лицензионную атрибуцию.

## Проверки

Перед Pull Request выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --require-hashes -r requirements.lock
ansible-galaxy collection install -r requirements.yml
bash scripts/validate.sh
```

Для изменения развёртывания дополнительно требуется приёмка на двух одноразовых
Ubuntu 24.04 VPS: первый deploy, `changed=0`, reboot и `awg-health --strict`.

## Названия коммитов

Название коммита пишется по-русски в форме существительного, описывающего
результат изменения: `Добавление…`, `Исправление…`, `Улучшение…`, `Удаление…`,
`Обновление…` или `Проверка…`. Не используйте повелительную форму
`Добавить…`, `Исправить…`, `Улучшить…` или `Удалить…`.

## Pull Request

Опишите причину, изменения, влияние на пользователей, выполненные проверки и
план отката. Добавляя код, вы соглашаетесь распространять свой вклад по лицензии
MIT проекта. Лицензии сторонних компонентов продолжают действовать независимо.
