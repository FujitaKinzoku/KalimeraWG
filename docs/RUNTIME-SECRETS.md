# Пороговая защита секретов

KalimeraWG хранит чувствительную конфигурацию серверов в одном
аутентифицированном пакете `AES-256-GCM`. Открытая копия существует только в
`/run/kalimera-secrets` и исчезает при выключении VPS. Службы получают свои
конфигурации через изолированные credentials systemd.

## Что защищается

| Данные | Состояние на диске | Состояние при работе |
|---|---|---|
| AWG и AWG 3+ private key/PSK/config | только зашифрованный пакет | `/run` + credential службы |
| sing-box и учётные данные SOCKS5 | только зашифрованный пакет | `/run` + credential службы |
| локальные peer-файлы и клиентские конфигурации | только зашифрованный пакет | `/run`, root-only |
| Telegram token и локальные DNS/proxy overrides | только зашифрованный пакет | `/run` + credential/защищённый путь |
| пароль production Vault и SSH-ключ оркестратора на локальном ENTRY | только зашифрованный пакет | `/run`, root-only |

Списки пакетов, контрольные суммы, публичные ключи, адреса серверов и сами
Shamir-доли не являются содержимым пакета. Одна доля не позволяет получить
ключ шифрования.

## Схема 2-of-5

Установщик создаёт случайный 256-битный ключ и делит его настоящей схемой
Shamir Secret Sharing из пакета Ubuntu `ssss`.

| Доля | Назначение |
|---|---|
| 1 | ENTRY |
| 2 | основной EXIT |
| 3 | зарезервирована для будущего второго EXIT |
| 4 | зарезервирована для отдельного держателя/брокера |
| 5 | внешняя аварийная копия владельца |

Для открытия нужны любые две разные доли. На каждом сервере постоянно хранится
только его собственная доля и отдельный SSH-ключ, которому разрешена ровно одна
forced-команда выдачи доли. SSH host keys закреплены; запрос ограничен адресом
peer-сервера. При загрузке SSH доступен раньше каскада, поэтому ENTRY и EXIT
могут взаимно собрать ключ даже после одновременной перезагрузки.

Если кворум временно недоступен, запуск ждёт его ограниченное время. После
тайм-аута AWG, AWG3, sing-box и мониторинг не получают конфигурацию и остаются
остановленными: система работает fail-closed и не создаёт открытую копию на
диске.

## Резервная доля

После успешной установки сохраните долю №5 на отдельный зашифрованный носитель,
не на ENTRY или EXIT:

```bash
python3 scripts/export-runtime-recovery-share.py \
  --repo-root /root/KalimeraWG \
  --vault-password-file /root/.config/awg-iac/production-vault.pass \
  --share-index 5 \
  --output /media/ENCRYPTED/kalimerawg-recovery.share
```

Скрипт создаёт файл с правами `0400`, отказывается писать внутрь репозитория и
не печатает долю на экран. Для ручного восстановления укажите этот файл:

```bash
kalimera-secretctl unlock \
  --recovery-share-file /media/ENCRYPTED/kalimerawg-recovery.share
```

Не храните резервную долю рядом с диском сервера: сочетание локальной и
резервной долей отменит защиту копии этого диска.

## Второй EXIT

Контур секретов уже поддерживает несколько peers, параллельное получение долей
и уникальные индексы узлов. Когда поддержка второго EXIT в пакетном тракте
будет реализована, формат менять не потребуется: inventory автоматически
создаст отдельную identity, назначит долю №3 и обновит разрешённый список
держателей. Тогда потеря связи с одним из трёх серверов не помешает оставшимся
собрать `2-of-3` кворум. Доли №4 и №5 останутся вне серверного контура для
отдельного держателя и восстановления.

Это резервирование **хранилища ключей**, а не готовая балансировка VPN-трафика.
Текущий выпуск намеренно оставляет один активный маршрут ENTRY → EXIT, поэтому
новая защита не добавляет операций в пакетный тракт и не влияет на throughput,
latency, MTU или порядок маршрутизации. Перед включением второго EXIT в тракт
потребуется отдельная реализация уникального AWG peer, health-based policy
routing, сохранения conntrack-сессий и тестов асимметричного маршрута.
До появления этой реализации не добавляйте второй EXIT в production inventory.

## Проверки

| Проверка | Что подтверждает |
|---|---|
| `kalimera-secretctl verify` | `/run` открыт, постоянные пути являются только ссылками, права безопасны |
| `kalimera-secretctl check` | доступен кворум, ключ совпадает, AES-GCM и архив аутентичны |
| `awg-health --strict` | хранилище, systemd credentials и весь каскад исправны |
| `server-audit` | нет открытых копий и изменённых управляющих файлов |

CI дополнительно проверяет `2-of-3`, повторный идемпотентный `seal`, имитацию
перезагрузки и отказ при изменённом ciphertext.

## Границы защиты

Схема существенно защищает выключенный диск, snapshot или резервную копию
одной VPS. Она не защищает от root-доступа к работающему серверу, чтения RAM,
одновременного контроля двух активных держателей либо полного контроля
гипервизора хостером. `systemd credentials` уменьшают видимость секретов между
службами, но не являются отдельным фактором против root.
