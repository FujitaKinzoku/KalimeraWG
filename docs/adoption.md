# Безопасное принятие существующей инфраструктуры под управление

1. Собрать обезличенный inventory действующих серверов командами только для чтения.
2. Проверить полученный артефакт локальным сканером потенциальных секретов.
3. Описать желаемое состояние примерными значениями и зашифрованными production-переменными.
4. Локально сформировать предлагаемые конфигурации и проверить их синтаксис.
5. Сравнить нормализованные действующие и сформированные конфигурации без вывода секретов.
6. Проверить deploy, повторный deploy, health-check, reboot и rollback на чистых одноразовых VPS.
7. На рабочих серверах создавать восстановительные копии только в `/root/config-backups`.
8. Применять по одной подсистеме с handlers и проверкой состояния после изменения.
9. При первоначальном принятии не удалять существующих peers, Docker и legacy-файлы.

## Обязательные проверки на чистых VPS

- Первый deploy завершается успешно.
- Второй deploy не сообщает об изменениях.
- После перезагрузки восстанавливаются оба AWG-интерфейса и необходимые таймеры.
- Обычный трафик ENTRY получает mark `0x1` и направляется через EXIT.
- При исправном прокси RU-трафик получает mark `0x2` и направляется через `sb-ru`.
- Отказ RU-прокси включает прямой выход через ENTRY, после восстановления возвращается прокси-режим.
- Обычный DNS использует Unbound DoT, RU DNS — Yandex DoH через SOCKS.
- Настроенные RU direct-порты обходят прокси; TCP/25 не добавляется автоматически.
- NAT, MSS, UFW, Fail2Ban и изоляция клиентов на EXIT остаются корректными.
- Rollback восстанавливает предыдущую конфигурацию без копирования backup за пределы `/root/config-backups`.
