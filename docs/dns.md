# DNS каскада

Клиенты спрашивают имена только у ENTRY, внутри зашифрованного туннеля. Дальше
запрос идёт по одному из путей, в зависимости от имени.

```
Устройство (AmneziaWG или VLESS)
   │  внутри туннеля
   ▼
dnsmasq на ENTRY: раскладывает имена по спискам, своего кэша нет
   ▼
Unbound на ENTRY (127.0.0.1:5353): кэш в памяти, проверка DNSSEC, журналов нет
   ├─ .ru, .рф, ru-domain, entry-domain → российский резолвер по DoT, с ENTRY
   └─ все остальные имена → серверы DoT с ENTRY либо резолвер EXIT в туннеле
```

- Любой обычный запрос DNS клиента, к какому бы серверу он ни шёл, перенаправляется
  на dnsmasq ENTRY. DoT клиентов (порт 853) отклоняется, служебные имена DoH
  браузеров получают ответ «нет такого имени».
- Адреса имён из списков dnsmasq кладёт в наборы, по которым маршрутизация
  выбирает путь трафика.
- Запросы нигде не записываются; кэш Unbound только в памяти.
- Текущее состояние показывает `dns-status`.

## Зарубежные имена: два режима

| | Серверы DoT (по умолчанию) | Резолвер EXIT |
|---|---|---|
| Откуда уходит запрос | с ENTRY, зашифрованным, на зарубежный сервер DoT | с ENTRY наружу не уходит: идёт в туннель |
| Что видит российский хостер | подключения ENTRY к серверу DoT, без имён | ничего, кроме трафика туннеля |
| Кто видит имена | оператор сервера DoT | никто из сторонних резолверов; серверы имён видят запросы от адреса EXIT |
| Первый запрос нового имени | быстрее | дольше: путь через туннель и полный обход серверов имён |
| Ответы CDN | для места сервера DoT | для места EXIT, откуда и выходит трафик (с резервным EXIT - одного из двух серверов) |

Российские имена в обоих режимах разрешает российский резолвер с ENTRY: трафик
к этим сайтам и так выходит с ENTRY.

### Включение

На ENTRY:

```bash
kalimera-deploy --resume --enable-dns-via-exit
```

На EXIT (и на резервном EXIT, если он подключён) ставится собственный резолвер
Unbound с проверкой DNSSEC. Он слушает только адрес туннеля и отвечает только
ENTRY. Unbound на ENTRY пересылает ему зарубежные имена.

Deploy настраивает ENTRY раньше, чем EXIT. Поэтому при включении ENTRY остаётся на
серверах DoT, пока резолвер EXIT не ответит по туннелю, и переводится на него в
конце того же запуска: зарубежные имена не перестают разрешаться на время
установки. Если резолвер EXIT так и не ответил, запуск завершается ошибкой, а
имена остаются на серверах DoT; `cascade-check` показывает это замечанием.

Выключение:

```bash
kalimera-deploy --resume --disable-dns-via-exit
```

### С резервным EXIT

Unbound пересылает зарубежные имена резолверам обоих EXIT, каждому по его
туннелю, и сам обходит тот, что не отвечает. На стенде пропадание одного туннеля
на 200 секунд не оставило без ответа ни одного запроса из двухсот: ответы шли
через второй резолвер. Разрешение имён поэтому не ждёт, пока переключатель путей
переведёт трафик, и не зависит от отказа резолвера на одном из серверов.
`dns-status` показывает оба адреса.

Цена: часть имён разрешается для места резервного EXIT, а не того, через который
сейчас идёт трафик. Для двух серверов в одном регионе разницы практически нет.
Переменная `entry_dns_via_exit_both: false` оставляет один резолвер - сервера,
через который идёт трафик; тогда пересылку между серверами переводит
переключатель путей.

### Потери и сбои связи

Резолверы EXIT стоят за туннелями, поэтому важны два случая. Оба измерены на
стенде с Unbound той же версии, что на серверах (1.19.2).

- **Потери в туннеле** пересылка переносит. При 7% потерь в каждую сторону
  половина новых имён разрешалась за те же 90 мс, что и без потерь, 99% - не
  дольше секунды. Пересылка по TCP и увеличенный тайм-аут повтора оказались
  хуже и не применяются.
- **Связь со всеми резолверами пропала дольше трёх минут** (у каскада один EXIT,
  не отвечают оба или пропала связь у самого ENTRY). Сервер пересылки, который
  столько не отвечал, Unbound считает неработающим и перестаёт к нему
  обращаться. Без принятых мер после возвращения связи зарубежные имена не
  разрешались: на стенде за 150 секунд не ответил ни один запрос. Меры две:
  Unbound продолжает проверять такой сервер, а сведения о нём живут минуту -
  ответы возвращаются сами через 20-30 секунд; переключатель путей сбрасывает
  эти сведения сразу, как только путь, несущий трафик, снова ответил.

В режиме серверов DoT действует первая мера: после такого же сбоя ответы
возвращаются примерно через полторы минуты.

### Что учесть

- Пока не отвечает ни один EXIT, зарубежные имена не разрешаются вовсе, в том
  числе для самого ENTRY: например, `git fetch` с GitHub не пройдёт. Вернуть
  серверы DoT можно без доступа к EXIT: `--disable-dns-via-exit`.
- Действующий режим на серверы DoT сам не возвращается, даже если EXIT во время
  deploy не отвечает: запросы о зарубежных узлах не должны уходить с ENTRY.
- `dot-switch` в этом режиме отказывает: серверы DoT не используются.
