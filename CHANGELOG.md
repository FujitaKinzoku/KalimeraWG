# Журнал изменений

## [Unreleased] - фиксация тестового этапа

- В отдельной ветке профиль `mobile` заменён на `mobile/AWG3+` для клиента
  AmneziaWG 5.0.1.5 или новее. Он использует отдельные закреплённые userspace
  сборки AWG 3.1 и не изменяет проверенный межсерверный AWG 3.0.
- Серверные и клиентские конфиги mobile/AWG3+ получают полный поддерживаемый
  набор `J/S/H/I1-I5`, `HeaderProtectionKey`, padding, rekey, keepalive,
  `RandomTrailers` и `DisableCookies`. Добавлены миграция Vault, systemd
  credentials, ролевые health-проверки и генерация через `vpn-user`.
- Старый частичный переключатель `--mobile-i1-mode` удалён. При переходе со
  старого mobile-профиля его клиентские конфиги требуется выпустить заново.
- Таблицы `kalimera-status` и приветственной справки получили единый
  адаптивный рендер для ролей ENTRY, EXIT и FRONT. Заголовок теперь находится
  внутри рамки, ширина колонок одинакова для однотипных разделов, а длинные
  команды и значения переносятся внутри ячейки. Правая граница больше не
  уходит за пределы окна и не оставляет отдельные вертикальные линии.
- Исправлена обязательная проверка VLESS Encryption на FRONT. Xray-core
  использует разные форматы согласованной ML-KEM-768 пары: серверный
  `decryption` начинается с `mlkem768x25519plus.native.600s.`, а клиентский
  `encryption` с `mlkem768x25519plus.native.0rtt.`. Прежняя проверка ошибочно
  требовала клиентский формат от обеих сторон и блокировала корректные чистые
  установки и `--resume`. Интеграционный тест теперь получает пару настоящим
  закреплённым Xray-core и отдельно проверяет серверную конфигурацию и полный
  клиентский JSON.
- Экспорт `vless-user` для режима CDN приведён к подтверждённому формату
  полного JSON-профиля HAPP: SOCKS и HTTP inbounds, sniffing, DNS, VLESS
  Encryption, TLS ALPN/fingerprint, полный XHTTP camouflage, routing и
  служебные outbounds. Клиентский JSON теперь дополнительно проверяется
  закреплённым Xray-core с включёнными ML-KEM-768 и XHTTP disguise.
  Дополнительный слой VLESS Encryption теперь обязателен для управляемого
  FRONT: установщик сохраняет переключатель в production inventory, а Xray
  создаёт согласованную пару ML-KEM-768 `decryption`/`encryption` атомарно.
  Для уже работающего каскада добавлен отдельный playbook точечного обновления
  без повторного применения остальных ролей. Он проверяет обе стороны пары и
  кратко перезапускает только Xray на FRONT; Nginx, CDN, UFW, ENTRY и EXIT не
  изменяются. `awg-health --strict` отдельно контролирует, что ML-KEM-768
  включён и в серверной конфигурации, и в параметрах клиентского JSON.
  Автономный playbook получает действующие публичные параметры REALITY из
  защищённого runtime-каталога ENTRY и не зависит от временных `set_fact`,
  существовавших только во время полного deploy.
- Исправлен первый запуск `awg-ru-zone-update` на чистом ENTRY с включённым
  FRONT: публичные rule-set вынесены в отдельный каталог, доступный службе на
  запись без открытия каталога закрытых ключей REALITY. Повторный deploy
  проверяет полноту производного списка, даже если основной кэш успел
  сохраниться до прерывания установки. Unit рендерится без склеивания соседней
  директивы systemd при включённом FRONT.
- Документация ветки `feature/vless-reality-fallback` обновлена после успешной
  полевой проверки при активном режиме белых списков: зафиксирован маршрут
  через совместимый облачный CDN → FRONT → ENTRY и подтверждено сохранение
  существующих
  RU/EXIT-политик после входа в каскад.
- В README добавлена единая схема трёх альтернативных входов (AWG, прямой
  REALITY и CDN/XHTTP), таблица транспортов и границы подтверждённого теста.
- Расширено описание FRONT: послойная технология, матрица отказов,
  эксплуатационные проверки и явно отделённые от текущего этапа будущие
  улучшения. Исполняемые роли, шаблоны и скрипты в этом этапе не изменялись.

## [2.1.0] - 2026-08-19

- Добавлена новая опциональная роль `exit_dns`: полная DNSSEC-валидирующая
  рекурсия Unbound на EXIT (без стороннего апстрима), с QNAME minimisation,
  доступная только ENTRY по AWG-каналу. Дефолтная/зарубежная ветка
  системного DNS на ENTRY может резолвиться через неё вместо внешнего DoT -
  DNS-запрос идёт внутри уже существующего зашифрованного ENTRY–EXIT
  туннеля, и с ENTRY больше не уходит отдельный TLS ClientHello к стороннему
  DNS-провайдеру. Переключатель `entry_dns_default_via_exit` по умолчанию
  выключен - обратная совместимость сохранена. RU-ветка (`.ru`/`.рф`,
  `ru-domain`) не затронута.
- Резолвинг любого `.ru`/`.рф` теперь автоматически добавляет полученный IP
  в ipset `ru` (тем же механизмом `dnsmasq --ipset`, что уже используется
  для `ru-domain`/`se-domain`) - закрывает дрейф CDN, когда российский
  сервис отдаёт адрес из общего с зарубежными сайтами IP-пула.
- Устранена неоднозначность выбора DNS-сервера для `ru-domain` и
  автоматического `.ru`/`.рф`-сплита: раньше для одного домена
  конкурировали две строки `server=` (RU-DoH и дефолтная ветка), и dnsmasq
  мог по внутренней эвристике молча выбрать не ту - при включённом
  RU-прокси остаётся только RU-DoH, недоступность которого теперь даёт
  честный отказ резолвинга вместо утечки геолокации через дефолтную ветку.
- Отдельная роль `security` теперь также управляет UFW-правилом для
  рекурсивного DNS EXIT - отпечаток управляемой политики UFW фиксируется в
  конце роли `security`, и правило, добавленное другой ролью после этого
  момента, всегда считалось бы расхождением со снимком.

## [2.0.1] - 2026-08-18

- Системный резолвер ENTRY принудительно переключается на `systemd-resolved`
  независимо от провайдера VPS: `/etc/resolv.conf` приводится к симлинку на
  `stub-resolv.conf`, а `nsswitch.conf` гарантированно содержит NSS-модуль
  `resolve`. На части провайдеров cloud-init однократно перезаписывает
  `/etc/resolv.conf` собственным DNS хостера в обход Unbound, из-за чего
  `getent`/приложения на Python (в том числе проверка `ru-proxy`) резолвили
  имена напрямую через хостера и блокировались строгим UFW.

## [2.0.0] - 2026-08-18

- Локальный ENTRY больше не проверяет адресно ограниченный automation root key
  через `127.0.0.1`: локальный Ansible transport уже подтверждает доступ, а
  внешний вход `kalimera` по-прежнему требует отдельного подтверждения
  оператора. Удалённые ENTRY/EXIT продолжают обязательную root-key проверку.
- Устранена гонка отложенного перезапуска межсерверного AWG 3+: перед каждым
  запуском очищается только управляемый stale-интерфейс и control socket,
  systemd дожидается остановки process group, а обработчик выполняет три
  ограниченные попытки и при отказе показывает безопасную диагностику без
  ключевого материала.
- Четыре одноразовых пароля `kalimera`/`root` для ENTRY и EXIT теперь выводятся
  после успешной итоговой сводки. До этого момента они существуют только в
  памяти установщика; после оборванной установки `--resume` перевыпускает ещё
  не показанные пароли, а после показа сохраняется только несекретный признак,
  предотвращающий их изменение при обычных обновлениях.
- Интерактивная установка создаёт отдельного администратора `kalimera`,
  переносит человеческий key-only SSH-доступ на него и оставляет root SSH
  только как ограниченный по адресу канал автоматизации там, где он необходим
  для повторного управления удалённым узлом.
- Для `kalimera` и `root` каждого сервера генерируются независимые 30-символьные
  пароли всех классов. Они показываются оператору один раз, а в Vault остаются
  только необратимые SHA-512 crypt-хеши. Рабочие команды доступны `kalimera`
  без явного `sudo` через root-owned allowlist, но произвольный passwordless
  root shell не предоставляется.
- Первоначальный SSH-пользователь VPS может быть `root`, `ubuntu` или другим
  sudo-пользователем: после подтверждения нового доступа inventory переключает
  автоматизацию на отдельный root key с адресным ограничением, а введённые
  bootstrap/become-пароли удаляются даже из зашифрованного Vault.
- Обмен долями runtime-секретов переведён с root SSH на отдельный forced-command
  ключ пользователя `kalimera`; sudo разрешает этому ключу только выдачу одной
  локальной доли заданного кластера.
- DKMS guard обнаруживает не только `/vmlinuz`, но и все установленные образы,
  каталоги модулей и signed/unsigned kernel packages, после чего проверяет
  AmneziaWG для работающего и наиболее нового загрузочного ядра.
- Добавлена пороговая защита постоянных секретов: настоящий Shamir `2-of-5`,
  аутентифицированный пакет AES-256-GCM, открытые данные только в `/run` и
  передача конфигураций AWG/AWG3/sing-box/Telegram через credentials systemd.
- Загрузка стала fail-closed: службы ждут ограниченное время появления второй
  доли, проверяют закреплённые SSH host keys и не запускаются с отсутствующим
  либо изменённым пакетом; `awg-health` и `server-audit` проверяют кворум.
- CI имитирует перезагрузку, повторный идемпотентный seal и повреждение
  ciphertext. Обмен долями поддерживает будущий второй EXIT без изменений
  текущего пакетного тракта и без влияния на скорость каскада.
- Удалена отсутствующая в Unbound из Ubuntu 24.04 директива `log-destaddr`;
  CI теперь формирует DNS-конфигурацию и проверяет её настоящим
  `unbound-checkconf` до чистого развёртывания.
- Для образов VPS без Ed25519 SSH host key установка теперь создаёт только
  отсутствующую пару, восстанавливает публичную часть из закрытой, проверяет
  SHA-256 fingerprint и закрепляет Ed25519 в эффективной политике `sshd`.
- Политика no-logs для journald получила последний приоритет; health/audit
  проверяют именно итоговое значение параметров, а `sshd` больше не загружает
  устаревший DSA host key даже при его наличии в образе VPS.
- Подготовлен единый пакет усиления безопасности без отдельных режимов
  установки и без изменения портов, MTU, DNS-политик или маршрутов каскада.
- SSH скрывает системный banner, запрещает пользовательские startup-файлы и
  ограничивает ключ автоматизации адресом управляющего узла; отдельный
  административный ключ сохраняет возможность восстановления.
- Клиентские AWG-зоны изолированы друг от друга, от cloud metadata и от
  служебной подсети ENTRY–EXIT, сохраняя доступ к локальному DNS и Интернету.
- PPA AmneziaWG переведён на отдельный `Signed-By` keyring с проверкой полного
  отпечатка; обновления, DKMS и откат остаются совместимыми с новыми пакетами.
- Добавлены безопасные sysctl/systemd-настройки и единая политика no-logs:
  journal/Fail2Ban/учёт входов работают только в RAM, UFW/sing-box/DNS query
  logs, shell history и coredump не сохраняются; `server-audit` проверяет
  соблюдение этой политики.
- Генераторы AWG-профилей проверяют синтаксис CPS, непересечение заголовков и
  размер пакетов относительно минимального IPv4 PMTU до применения настроек.
- Mermaid-схема каскада заменена на адаптивные SVG для русского и английского
  README: единая типографика, фиксированная сетка и раздельные цветовые маршруты.
- Добавлены проверенная матрица совместимости, формы безопасного сообщения об
  ошибках и предложениях, шаблон Pull Request, правила сообщества и отдельный
  Social Preview без изменения исполняемого кода или выпуска `v1.0.0`.

Формат основан на Keep a Changelog. Проект использует семантические номера
версий для публичных выпусков.

## [1.0.0] - 2026-08-15

Первый стабильный выпуск. Проверен последовательными чистыми установками ENTRY
и EXIT, клиентскими профилями, DNS, RU-прокси, перезагрузкой и строгим аудитом.

### Безопасность

- Секреты остаются в Ansible Vault и root-only runtime-файлах; задачи с
  ключевым материалом используют `no_log`, а CI проверяет дерево и историю
  Gitleaks и отдельным secret scan.
- Новый key-only SSH-доступ подтверждается до закрытия старого порта и включения
  Fail2Ban; аварийный сценарий не расширяет внешний периметр.
- UFW применяет запрещающие входящую и транзитную политики. Межсерверный AWG3
  разрешён только между заранее известными публичными IPv4 ENTRY и EXIT.
- Обновление AmneziaWG, sing-box и AWG3 стало транзакционным: кандидаты
  проверяются, фактически применённые версии фиксируются, а ошибка запуска
  вызывает автоматический откат ENTRY и EXIT.
- Перед перезагрузкой проверяются заголовки, DKMS и модуль AmneziaWG для
  текущего и следующего ядра.
- Ошибка запуска AWG3 выводит только очищенные systemd/interface/port данные;
  содержимое конфигурации, private key и PSK не печатаются.
- Отключение IPv6 изменяет только несовместимые IPv6-hooks `ifupdown`, не
  затрагивая IPv4, шлюз и DNS хостинга. Сетевой менеджер VPS не заменяется.

### Надёжность

- Добавлены ограниченные повторные попытки и тайм-ауты для DNS, APT, SSH
  bootstrap и запуска AWG3; зависшая установка больше не ждёт сеть бесконечно.
- Системный резолвер ENTRY переводится на проверенный локальный Unbound, а
  отказ DNS провайдера не вызывает ложный fail-open RU-прокси.
- Кратковременный timeout SOCKS5 при повторном deploy передаётся штатному
  watchdog/fail-open и не разрушает ранее подтверждённую конфигурацию.
- `ipset` устанавливается до sing-box. Недоступное или небезопасное зеркало APT
  диагностируется без самовольной замены сетевой конфигурации хостинга.
- AWG3 получает три ограниченные попытки запуска; постоянный отказ формирует
  безопасный диагностический отчёт и останавливает цикл перезапусков.
- Двусторонний PMTU, согласованный MTU и MSS clamp применяются ко всем сегментам
  каскада.

### Функциональность

- Раздельные профили `performance`, `balanced`, `masking`, `mobile` и `old`;
  mobile использует отдельный QUIC-подобный интерфейс UDP/8443.
- Отдельный userspace-канал AWG 3+ ENTRY–EXIT с независимыми ключами, PSK и
  расширенными параметрами.
- Управляемые DoT/DoH, доменные политики ENTRY/EXIT/RU, SOAX/SOCKS5 TUN,
  watchdog и fail-open.
- Команды просмотра и удаления клиентов, DNS, маршрутов, proxy, обслуживания,
  аудита и безопасной проверки Telegram.
- Адаптивные Kali-подобные таблицы состояния и справки при SSH-входе.
- Внешний IPv4 локального ENTRY определяется автоматически; `127.0.0.1`
  используется только для действительно локального управления.

### Выпуск

- Добавлен единый файл `VERSION`; `./deploy --version` показывает установленный
  выпуск.
- `install.sh` по умолчанию загружает неизменяемый тег `v1.0.0` и проверяет
  соответствие версии файлов выбранному выпуску.
- README сокращён и преобразован в обзор с таблицами, Mermaid-схемой и ссылками
  на подробную техническую документацию.

## [0.2.0-rc.1] - 2026-08-11

Первый кандидат KalimeraWG подготовлен из проверенного рабочего
снимка `7c8a0d42075739141e40e6e5d530a6d9ecd9e59e` с новой чистой Git-историей.
Функциональный код снимка не изменён; обновлены название, адреса установки,
документация и правила ответственного использования.

### Изменено

- административные команды теперь строго проверяют аргументы; `f2b-reset` по
  умолчанию только показывает состояние и снимает блокировки лишь по явному IP
  или параметру `--all`;
- обновления и обслуживание больше не очищают глобально список неисправных
  systemd-модулей, а завершаются полным `server-audit`;
- применение доменных и базовых DNS-политик стало транзакционным, а локальные
  peer-файлы полностью проверяются до изменения живых AWG-интерфейсов;
- защита обновлений ядра теперь проверяет фактически зарегистрированный модуль
  `amneziawg` в DKMS, а не требует конкретное имя Debian-пакета
  `amneziawg-dkms`; актуальные и ранее развёрнутые варианты упаковки
  поддерживаются без ослабления проверки сборки для каждого ядра;
- UFW теперь сохраняет запрет ICMP echo после каждой перезагрузки и больше не
  отменяет общую политику KalimeraWG своим поздно загружаемым `sysctl.conf`;
- `maintenance` и `update-all` устанавливают недостающие заголовки, запускают
  DKMS и проверяют AmneziaWG для текущего и следующего загрузочного ядра до
  успешного завершения обслуживания;
- повторный `deploy --resume` сохраняет ранее подтверждённый режим RU UDP при
  кратковременном timeout SOCKS5 и передаёт отказ штатному fail-open/watchdog;
  чистая установка по-прежнему останавливается, если новый прокси не проверен;
- Telegram-мониторинг различает исправное, резервное и неисправное состояния,
  сообщает о перезагрузке сервера, автоматическом fail-open и восстановлении
  RU-прокси; команда `telegram-test` проверяет доставку без создания сбоя;
- установщик получил Kali-подобное разделение этапов и структурированный
  итоговый экран с адресами, маршрутами, DNS, MTU, файлами и следующими шагами;
- экран при SSH-входе использует тот же адаптивный табличный рендерер для
  текущей конфигурации и всех групп команд; добавлен исполняемый тест
  сформированного экрана ENTRY/EXIT, включая проверку типов Ansible boolean;
- добавлен режим `./deploy --terminal-only`, обновляющий только терминальное
  оформление и справку на обоих серверах без SSH-перехода и изменения каскада;
- проверка репозитория запускает `check-secrets.sh` через Bash и больше не
  зависит от исполняемого бита файла на чистой Ubuntu;
- новые установки используют `ENTRY:443/UDP` для клиентов и `EXIT:443/UDP`
  для публичного endpoint межсерверного AWG 3+;
- локальный AWG3-порт ENTRY выбирается отдельно и остаётся доступен только
  известному IPv4 EXIT сервера;
- современные клиентские и межсерверные профили используют индивидуальный
  1200-байтный QUIC Initial-подобный `I1` и ограниченные QUIC-подобные `I2–I5`.
- mobile-интерфейс переведён с внешнего UDP/53 и перенаправления на прямой
  UDP/8443; старые правила UDP/53 → UDP/39746 удаляются при обновлении;
- включение дополнительных интерфейсов больше не сбрасывает общие таблицы
  маршрутизации и не перезапускает `dnsmasq` в режиме `bind-dynamic`.
- клиентские адреса теперь используют префикс своей VPN-подсети вместо `/32`,
  чтобы Keenetic автоматически создавал связанный маршрут к внутреннему DNS;
  избыточный DNS `/32` удалён из клиентского `AllowedIPs`, а обязательный
  серверный peer `/32` сохранён.
