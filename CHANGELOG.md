# Журнал изменений

## Не выпущено

- При отключении IPv6 установщик теперь резервирует и комментирует только
  несовместимые IPv6-hooks в конфигурациях `ifupdown`, не затрагивая IPv4,
  шлюз и DNS провайдера.
- `systemd-networkd-wait-online` отключается только тогда, когда основной WAN
  явно не управляется `systemd-networkd`; активный сетевой менеджер при этом не
  останавливается и не переключается.
- Системный резолвер ENTRY направлен на локальный Unbound после его проверки;
  это устраняет ложный fail-open RU-прокси при недоступном DNS провайдера.
- Ошибки разрешения имён, внешней сети и конфигурации больше не отображаются
  терминалом как ошибки аргументов или синтаксиса.
- Добавлена ранняя проверка системного DNS до остановки APT-таймеров и изменения серверов.
- Для APT включены ограниченные повторные попытки и сетевые тайм-ауты.
- `ipset` перенесён в начальный набор зависимостей, до запуска `sing-box`.
- Установщик предупреждает об APT-источниках с `trusted=yes`, не изменяя зеркала провайдера автоматически.

Формат основан на Keep a Changelog. Проект использует семантические номера
версий для публичных выпусков.

## [0.2.0-rc.1] — 2026-08-11

Первый кандидат KalimeraWG подготовлен из проверенного рабочего
снимка `7c8a0d42075739141e40e6e5d530a6d9ecd9e59e` с новой чистой Git-историей.
Функциональный код снимка не изменён; обновлены название, адреса установки,
документация и правила ответственного использования.

### Изменено

- административные команды теперь строго проверяют аргументы; `f2b-reset` по
  умолчанию только показывает состояние и снимает блокировки лишь по явному IP
  или параметру `--all`;
- обновления и обслуживание больше не очищают глобально список неисправных
  systemd-модулей, а завершаются полным `server-audit`;
- применение доменных и базовых DNS-политик стало транзакционным, а локальные
  peer-файлы полностью проверяются до изменения живых AWG-интерфейсов;
- защита обновлений ядра теперь проверяет фактически зарегистрированный модуль
  `amneziawg` в DKMS, а не требует конкретное имя Debian-пакета
  `amneziawg-dkms`; актуальные и ранее развёрнутые варианты упаковки
  поддерживаются без ослабления проверки сборки для каждого ядра;
- UFW теперь сохраняет запрет ICMP echo после каждой перезагрузки и больше не
  отменяет общую политику KalimeraWG своим поздно загружаемым `sysctl.conf`;
- `maintenance` и `update-all` устанавливают недостающие заголовки, запускают
  DKMS и проверяют AmneziaWG для текущего и следующего загрузочного ядра до
  успешного завершения обслуживания;
- повторный `deploy --resume` сохраняет ранее подтверждённый режим RU UDP при
  кратковременном timeout SOCKS5 и передаёт отказ штатному fail-open/watchdog;
  чистая установка по-прежнему останавливается, если новый прокси не проверен;
- Telegram-мониторинг различает исправное, резервное и неисправное состояния,
  сообщает о перезагрузке сервера, автоматическом fail-open и восстановлении
  RU-прокси; команда `telegram-test` проверяет доставку без создания сбоя;
- установщик получил Kali-подобное разделение этапов и структурированный
  итоговый экран с адресами, маршрутами, DNS, MTU, файлами и следующими шагами;
- экран при SSH-входе использует тот же адаптивный табличный рендерер для
  текущей конфигурации и всех групп команд; добавлен исполняемый тест
  сформированного экрана ENTRY/EXIT, включая проверку типов Ansible boolean;
- добавлен режим `./deploy --terminal-only`, обновляющий только терминальное
  оформление и справку на обоих серверах без SSH-перехода и изменения каскада;
- проверка репозитория запускает `check-secrets.sh` через Bash и больше не
  зависит от исполняемого бита файла на чистой Ubuntu;
- новые установки используют `ENTRY:443/UDP` для клиентов и `EXIT:443/UDP`
  для публичного endpoint межсерверного AWG 3+;
- локальный AWG3-порт ENTRY выбирается отдельно и остаётся доступен только
  известному IPv4 EXIT сервера;
- современные клиентские и межсерверные профили используют индивидуальный
  1200-байтный QUIC Initial-подобный `I1` и ограниченные QUIC-подобные `I2–I5`.
- mobile-интерфейс переведён с внешнего UDP/53 и перенаправления на прямой
  UDP/8443; старые правила UDP/53 → UDP/39746 удаляются при обновлении;
- включение дополнительных интерфейсов больше не сбрасывает общие таблицы
  маршрутизации и не перезапускает `dnsmasq` в режиме `bind-dynamic`.
- клиентские адреса теперь используют префикс своей VPN-подсети вместо `/32`,
  чтобы Keenetic автоматически создавал связанный маршрут к внутреннему DNS;
  избыточный DNS `/32` удалён из клиентского `AllowedIPs`, а обязательный
  серверный peer `/32` сохранён.

### Добавлено

- `vpn-user list` и `vpn-user delete ИМЯ` для безопасного просмотра, отзыва и
  резервного копирования локально созданных клиентов;
- `dns-status`, постоянные и обратимые `dot-switch`/`doh-switch`, включая
  проверку DNS и сохранение локальных переопределений при повторном deploy;
- цветная тематическая справка `kalimera-help`, автоматически показываемая один
  раз при каждом новом SSH/терминальном сеансе;
- `kalimera-status` и автоматическая цветная сводка при входе: фактические
  подключения, текущий RU-маршрут, DoT/DoH, MTU, UFW, key-only SSH, Fail2Ban и
  результат ограниченного по времени `server-audit` без вывода секретов;
- идемпотентный `./deploy --resume --enable-mobile` для безопасного добавления
  отсутствующего mobile-интерфейса, ключа в Vault и профиля UDP/8443 в ранее
  установленный production inventory;
- обратимый режим `--mobile-i1-mode quic-ios` для 1200-байтного QUIC
  Initial-подобного `I1`, подтверждённого в официальном клиенте AmneziaWG для iOS без
  изменения mobile-порта, ключей, пиров и параметров `J/S/H`;
- профиль `mobile` с отдельным интерфейсом, ключом и подсетью, проверенным
  QUIC Initial-подобным `I1` для официального клиента AmneziaWG на iOS и
  динамическим включением прямого UDP/8443 без конфликта с локальным DNS;
- команды `awg-mobile status|on|off` и строгие проверки доступа к порту,
  маршрутизации, DNS и состояния мобильного интерфейса;
- отдельная роль `terminal` с закреплённым `ble.sh`, подсветкой синтаксиса,
  дополнением Bash, Kali-подобным prompt и безопасной резервной копией
  `/etc/bash.bashrc` в `/root/config-backups`.

### Планируется

- расширение матрицы реальных клиентских устройств;
- дополнительные автоматические проверки восстановления и обновления.

## [0.1.0] — 2026-08-07

### Добавлено

- интерактивное развёртывание ENTRY и EXIT серверов на Ubuntu 24.04;
- отдельный userspace-канал AmneziaWG 3+ между серверами;
- двустороннее определение PMTU и согласование MTU каскада;
- клиентские профили `performance`, `balanced`, `masking` и `old`;
- расширенные клиентские поля `S1–S4`, диапазоны `H1–H4` и `I1–I5`;
- раздельная маршрутизация через ENTRY, EXIT и SOAX/SOCKS5;
- DNS через Unbound DoT и Yandex DoH через RU-прокси;
- fail-open, watchdog, health gate, аудит и плановое обслуживание;
- укрепление SSH, UFW, Fail2Ban и хранение секретов в Ansible Vault;
- русский интерактивный интерфейс и автоматическое создание первого клиента.
